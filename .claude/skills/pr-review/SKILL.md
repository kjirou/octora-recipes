# PR レビューのルール

PR やブランチ差分のレビューを依頼された時は、以下に従うこと。

## code-review スキルを使わない

ビルトインの `/code-review` スキル（Skill `code-review`）は**使わない**。自分で diff を読んでレビューする。

理由（ユーザー判断。詳細は未検証）:

- スキルが判断する推奨レビューレベルがあまり合っていない
- medium 以下のレベルでは「些細」と判断された指摘が切り捨てられるが、その切り捨てが過剰

## 手順

1. **規模確認**: `gh pr diff <num> --stat` で変更ファイルと規模を把握する
2. **diff を読む**: `gh pr diff <num>` で差分全文を読む。必要に応じて `gh pr view <num>` で説明・紐付く issue を確認し、変更箇所周辺の既存コードも確認する
3. **指摘の検証**: 指摘は必ずコードで裏を取ってから書く。推測のまま指摘しない
4. **PR へ投稿**: レビューが終わったら、**レビュー内容を必ず PR へコメントとして投稿する**。会話での報告だけで終えない。投稿先・作法の詳細は Skill `github-issue-pr` の「PR レビュー」節に従う

## サブエージェントの使用

- サブエージェント（Agent / Workflow）を使いたい場合は、規模・用途によらず**実行前にユーザーへ確認する**。勝手に起動しない（過去に約20行の PR へ 10 エージェント・約47万トークンのレビューが走った事故がある）
